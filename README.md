# Планировщик задач

Учебный проект Левушкина Никиты Денисовича, группа 541.
Преподаватель: Кривоносова Н.В.

Приложение на C# и ASP.NET Core с браузерным интерфейсом. Данные хранятся в SQLite,
поэтому после перезапуска задачи и напоминания сохраняются. Внешние сервисы не нужны.

## Запуск из исходников

Нужен .NET 10 SDK. Из корня проекта:

```sh
dotnet run --project src/TaskPlanner --urls http://localhost:5080
```

Откройте `http://localhost:5080`. Нажмите «Создать аккаунт», укажите email и пароль
не короче 10 символов. Приложение не отправляет email и не проверяет владение адресом:
для учебной демонстрации email используется как уникальный логин.

В готовой Windows-сборке достаточно запустить `Запустить.cmd`. .NET уже включён.

## Что работает

- регистрация, вход, выход, access JWT и обновляемая HttpOnly refresh-cookie;
- создание, изменение, завершение, возврат в активные и удаление задач;
- поиск, фильтры по состоянию, сортировка по сроку и времени создания;
- проверки прав на сервере, а не только скрытые кнопки;
- общий доступ зарегистрированному пользователю: чтение или редактирование;
- фоновые напоминания за 30 минут до срока и о пропущенных сроках;
- постоянный список напоминаний и необязательные уведомления браузера.

Напоминание уникально для задачи, владельца и конкретного срока. Перенос срока
может создать новое напоминание. При закрытом браузере сервер продолжает работать,
но всплывающее уведомление требует открытой страницы и разрешения браузера.
Если сервер был выключен, пропущенные напоминания появятся после его запуска.

## Проверки

```sh
dotnet build src/TaskPlanner -c Release
dotnet run --project tests/TaskPlanner.Tests -c Release
python3 tests/api_test.py
```

HTTP-тесты сами запускают сервер на свободном локальном порту с отдельной временной
базой. Рабочие пользовательские данные не используются. При нестандартном пути
к SDK задайте `DOTNET_EXE`.

В GitHub Actions выполняются сборка и оба набора тестов. Задание `windows-package`
создаёт самостоятельную Windows x64-сборку, доступную в Artifacts завершённого запуска.

## Устройство проекта

`Models.cs` содержит модель и контекст EF Core. `Auth.cs` отвечает за токены.
`Reminders.cs` содержит worker и `INotifier`. `Program.cs` настраивает API и проверки
доступа. В `wwwroot` находится интерфейс без внешних JavaScript-зависимостей.

`App_Data` создаётся автоматически и исключён из Git: там база и локальный ключ JWT.
Не удаляйте эту папку, если нужны сохранённые задачи. Для удалённого развёртывания
обязательны HTTPS, резервное копирование и отдельный секрет `Authentication__Key`
(Base64, минимум 32 случайных байта). Учебную конфигурацию не следует открывать в интернет
как готовый многопользовательский сервис. После выхода access token действует до
истечения короткого срока, а refresh token сразу отзывается.

## Проверка на защите

1. Создать аккаунт и две задачи с разными сроками.
2. Проверить сортировку, изменить задачу, завершить и вернуть её в активные.
3. Создать задачу со сроком через несколько минут, дождаться напоминания.
4. Во втором браузере войти другим пользователем и показать отсутствие чужих задач.
5. Выдать ему доступ, затем отозвать.
6. Перезапустить сервер и показать сохранённые данные.
